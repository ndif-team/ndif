# transformers / numpy / accelerate are left unpinned, for nnsight to resolve, so
# a server install can't contradict the client library it runs blocks for. torch
# is installed by docker/Dockerfile instead — see the note below.
#
# The cost is that the image is only as reproducible as the day it was built.
# What a build resolved to is recoverable after the fact:
#   docker run --rm --entrypoint pip <image> freeze
# The 2026-08-04 test image resolved torch 2.13.0, transformers 5.14.1,
# numpy 2.5.1, accelerate 1.14.0.

# The client library the server runs traced blocks for. Tracked to the 0.8
# branch rather than a PyPI release: 0.8 has no tag yet, so setuptools-scm
# derives 0.7.1.devN from v0.7.0 and the release on PyPI is the older line.
# Installing from git is why the image needs `git` (see docker/Dockerfile).
# For local development `just up` bind-mounts your working nnsight checkout over
# this install (see the justfile / compose), so a code change on the client side
# is picked up without a rebuild.
# This tracks the branch tip, so every rebuild ships whatever 0.8 holds at
# build time. That keeps the server on the client library it is developed
# against while both move, and it costs reproducibility: two images built from
# the same ndif commit can carry different nnsight code. The 2026-08-04 rebuild
# moved 3 commits and touched intervention/serialization.py and
# tracing/util.py — the serialization path the server depends on — with nothing
# in this file to show it. Recover what a build actually resolved with
#   docker run --rm --entrypoint pip <image> freeze | grep nnsight
# and pin this line to that commit for anything that has to be reproducible.
git+https://github.com/ndif-team/nnsight.git@0.8

# The one exception to leaving transformers unpinned, and it is a floor, not a
# pin. Before 5.15 tensor parallelism does not shard a tied LM head's weight
# while still gathering its output, so any model with `tie_word_embeddings=True`
# — Llama-3.2, Qwen2.5, most small checkpoints — serves logits `tp_size` times
# too wide. Reproduced on this stack: a degree-4 Llama-3.2-3B returned width
# 513024 for a 128256 vocabulary, with the argmax still correct, so nothing
# short of checking the shape catches it. nnsight refuses to shard below this
# version (nnsight.modeling.tp.MINIMUM_TRANSFORMERS); the floor is here so the
# image never gets built into that state in the first place.
transformers>=5.15.0
